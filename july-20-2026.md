# Changelog — 20 July 2026

Branch: `backend` · Baseline: `b7acfdc`

Built the first working vertical slices of the platform: NGO and volunteer
onboarding wired to real persistence, superadmin monitoring, organization
"needs / offers" posting, and the public event listing with a volunteer apply
flow. Also fixed the authorization foundation that all of it depended on.

**Nothing was committed.** All changes are in the working tree.

---

## Breaking changes

### Role vocabulary unified

The server used `superadmin | volunteer | organisation` while the client used
`ngo | volunteer`, with nothing mapping between them. Canonical values now live
in `packages/shared/src/roles.ts` and both sides import them.

- `apps/native/src/store/auth-store.ts` — `UserRole` is now the shared `Role`.
- `apps/native/src/app/(ngo)/_layout.tsx` — guard compares `"organisation"`.
- `apps/native/src/app/role-select.tsx`, `src/app/index.tsx`,
  `src/components/profile-screen.tsx` — updated to match.
- The `(ngo)` route folder name is unchanged; only the role *value* moved.

### JwtGuard no longer assigns a default role

Previously every new user was force-assigned `volunteer` on their first
authenticated request, which happened during signup — defeating the role-select
screen entirely. `request.user.roles` is now empty until the user chooses, and
`AuthUser.role` is `Role | null`.

Role selection goes through `POST /api/users/me/role` and is **one-shot**:
changing it later would silently re-home an account's organization and
applications, so it requires a superadmin.

### Guest-mode backdoor removed

`setGuestMode()` in `auth-store.ts` faked an authenticated session. It was dead
code and is gone.

## Database (`packages/db`)

### New tables

| File | Tables |
|---|---|
| `schema/categories.ts` | `categories`, `organization_categories`, `user_categories` |
| `schema/events.ts` | `events`, `event_applications` |
| `schema/needs.ts` | `organization_needs`, `need_pledges` |

Design notes:

- `events.accepted_count` and `organization_needs.fulfilled_quantity` are
  denormalised so public listings avoid a per-row aggregate. Both are only
  mutated inside a transaction holding `SELECT … FOR UPDATE` on the parent row.
- `event_applications` has a unique index on `(event_id, volunteer_id)` — one
  application per volunteer per event is enforced by the database, not by an
  application-level check.
- `organization_needs.type` is `WANT` (asking for something) or `OFFER`
  (surplus to give away).
- Indexes added for the public feeds (`status + start_at`, `status + type`,
  `city`) and the superadmin verification queue.

### Changed tables

**`organizations`**
- New: `org_type` (`org_type` enum), `team_size`, `founding_year` — the
  onboarding wizard was already collecting these and throwing them away.
- New: `rejection_reason`, `reviewed_by`, `reviewed_at` for the review trail.
- New: unique index on `owner_user_id`, so a double-submitted onboarding form
  cannot create a duplicate NGO.
- New indexes on `verification_status` and `city`.

**`users`**
- New: `bio`, `city`, `state` (volunteer profile), `suspended_reason`,
  and `onboarded_at` — the completion signal for volunteers, who have no
  organization row to check.

### Relations

Reverse relations added on `organizations` (`events`, `needs`,
`organizationCategories`) and `users` (`ownedOrganizations`,
`organizationAdmins`).

Deliberately **not** added: `users → eventApplications / needPledges`. Those
tables reference `users` twice (actor + reviewer) and Drizzle cannot
disambiguate without `relationName`. Query them from the child side. The same
pre-existing ambiguity affects `users → userDocuments`.

### Seed

`packages/db/src/seed.ts` now seeds 10 cause categories alongside the three
roles, and reports counts.

## Server (`apps/server`)

Added `@nabhya/shared` as a dependency.

### Common infrastructure

- `common/audit/` — `AuditService` + global `AuditModule`. The `audit_logs` table
  existed but nothing wrote to it. Writes are fire-and-forget so an audit failure
  never fails the business operation.
- `common/utils/pagination.ts` — `toOffset` / `paginate`, the `Paginated<T>`
  envelope every list endpoint returns.
- `common/utils/rows.ts` — `takeFirstOrThrow`, for unwrapping `RETURNING` rows
  under `noUncheckedIndexedAccess` without scattering non-null assertions.
- `common/decorators/optional-auth.decorator.ts` — `@OptionalAuth()`. Anonymous
  callers pass; a valid token additionally populates `request.user` so the public
  event detail can show "Applied". An invalid/expired token reads as anonymous
  rather than 401, so a stale token can't break the public feed.
- `common/guards/roles.guard.ts` — short-circuits on `@Public()`, and throws a
  descriptive 403 instead of returning bare `false`.
- `common/guards/jwt.guard.ts` — optional-auth support, explicit suspended-account
  message, no default role assignment.
- `common/types/auth.ts` — `AuthUser` interface; `UserRole` re-exports the shared
  `Role`.

### Modules

| Module | Routes |
|---|---|
| `users` | `GET/PATCH /users/me`, `POST /users/me/role`, `GET/POST /users/me/documents` |
| `onboarding` | `GET /onboarding/status`, `POST /onboarding/organization`, `POST /onboarding/volunteer` |
| `organizations` | Public directory + detail; `GET/PATCH /organizations/me`, `GET/POST /organizations/me/documents` |
| `categories` | `GET /categories` (public) |
| `events` | Public feed + detail, volunteer apply/withdraw, `GET /events/me/applications` |
| `events` (org) | Full CRUD under `org/events`, applicant listing and accept/reject |
| `needs` | Public feed + detail, pledge, `GET /needs/me/pledges` |
| `needs` (org) | Full CRUD under `org/needs`, pledge listing and accept/reject/complete |
| `admin` | Overview, org + user monitoring and dossiers, moderation, document queues, audit log |

**50 routes total.** Verified by booting the app and enumerating the OpenAPI
document.

### Authorization and integrity rules

- Every organisation-scoped route resolves the org from the token via
  `OrganizationsService.requireOwnedOrganization` — an organization id is never
  accepted from the client. `requireVerifiedOrganization` additionally gates
  anything that becomes publicly visible, so an unverified NGO can draft but not
  publish.
- Public list endpoints inner-join `organizations` and filter on `VERIFIED` +
  `ACTIVE`, so unverified or suspended NGOs never surface (and pagination counts
  stay correct, which a post-filter would break).
- Accepting an applicant re-checks capacity inside the transaction against a
  locked event row — two admins reviewing simultaneously cannot overfill.
- Withdrawing after acceptance frees the seat. Re-applying after withdrawing
  reuses the existing row so the unique index still holds.
- Deleting an event with accepted volunteers **cancels** it instead; deleting a
  need with accepted pledges **closes** it. The record of what people committed
  to is never erased.
- Suspending an organization cancels its published events and closes its open
  needs, so volunteers stop seeing and applying to them.
- Verifying an identity document promotes the user's own `verification_status`.
- A superadmin cannot change their own account status.

## Client (`apps/native`)

### Data layer

- `lib/api/http.ts` — typed `get/post/patch/delete/getPage` that unwrap the
  server envelope; blank query params are stripped so filter UIs can bind
  directly to state; `apiErrorMessage` for user-facing error text.
- `lib/api/endpoints.ts` — rewritten. The previous file pointed at three routes
  that never existed (`/users/profile`, `/onboarding/complete`,
  `/onboarding/status`).
- `lib/api/services.ts` — thin typed clients per domain.
- `lib/api/query-keys.ts` — central key registry plus broad invalidation scopes.
- `lib/types/domain.ts` — response types for every screen.
- `lib/format.ts` — date/range/relative/progress formatting.

### Hooks (TanStack Query)

`hooks/use-profile.ts`, `use-events.ts`, `use-needs.ts`, `use-admin.ts`.

### Routing

`app/index.tsx` now treats the server as the source of truth: persisted store
state gets the user onto a screen instantly, then `GET /onboarding/status`
reconciles it (role revoked, org approved, account suspended). `auth-store` gained
`syncFromStatus()` for that.

New route groups registered in `app/_layout.tsx`: `(admin)` and public `events/`.

### Screens

**Onboarding**
- `(onboarding)/index.tsx` — the existing NGO wizard is untouched apart from its
  submit step: `StepReview` gained a `submitting` prop and the local-only
  `setOnboarded()` was replaced with a real API call. Zeroed numeric fields are
  sent as `undefined`, since the schema treats them as optional but rejects `0`.
- `(onboarding)/volunteer.tsx` — **new** 4-step volunteer wizard mirroring the
  NGO one: about you → location → causes → review.

**NGO**
- `(ngo)/needs.tsx` — post what you need or what you're giving away, filter by
  type, see pending responses, remove posts. Unverified orgs see a banner instead
  of the create button.
- `(ngo)/events.tsx` — event list with fill progress and pending-applicant
  counts, create sheet, applicant review.

**Volunteer**
- `(volunteer)/index.tsx` — Discover: the public needs feed with a one-tap
  pledge.
- `(volunteer)/events.tsx` — Browse / My applications tabs.
- `(volunteer)/donations.tsx` — pledges and their status.

**Public (no account required)**
- `events/index.tsx` — the public event directory.
- `events/[id].tsx` — event detail; applying prompts sign-in when signed out,
  and shows live application status when signed in.

**Superadmin**
- `(admin)/_layout.tsx` — Overview / NGOs / Volunteers tabs.
- `(admin)/index.tsx` — action queue first (anything awaiting a decision), then
  counters for organizations, people, events, applications and needs.
- `(admin)/organizations.tsx` + `components/admin/org-detail-sheet.tsx` — search
  and filter by verification state; the dossier shows details, owner, activity
  counts and documents, with approve / mark-under-review / reject / suspend.
- `(admin)/volunteers.tsx` + `components/admin/user-detail-sheet.tsx` — per-person
  participation history (which events, what outcome, what they pledged), ID
  documents, and suspend/reinstate.

### Shared components

`screen-shell.tsx` (`ScreenHeader`, `Surface`, `EmptyState`, `LoadingState`,
`ErrorState`, `FilterChips`), `status-pill.tsx` (pill + status→tone mappings),
`event-feed.tsx`, `event-form-sheet.tsx`, `need-form-sheet.tsx`,
`applicants-sheet.tsx`, `date-time-field.tsx`.

Two deliberate constraints:

- **No new UI dependencies.** `date-time-field.tsx` is a dependency-free date +
  time entry (masked `DD/MM/YYYY` + 24h `HH:MM`, relative shortcuts, rejects
  `31/02` and `25:00`) rather than adding a date-picker package.
- **Cards and pills are composed from `View` + `useTheme()` tokens, not the
  shadcn `Card`/`Badge`.** The Tailwind config is light-mode only (hard-coded
  hex, no dark variants) while every screen themes through `useTheme()` — a
  shadcn `Card` would render light-on-light in dark mode. Revisit if the Tailwind
  theme is made dark-aware.

## Known gaps

1. **File uploads don't exist.** Document URLs are text columns and the upload
   endpoints accept a URL string. Verification cannot complete end to end until
   S3/R2 is wired.
2. **No way to mint the first superadmin over HTTP.** `AdminService.grantSuperadmin`
   exists and is deliberately unrouted — call it from a script or set `user_roles`
   by hand, otherwise `(admin)` is unreachable.
3. **`drizzle-kit push` still runs on every non-production boot** and
   `src/migrations/` does not exist. Move to generated migrations before real
   data lands.
4. **Still unbuilt:** monetary donations/payments, certificates, reviews,
   bookmarks, notifications, announcements, financial reports.
